==========================================================
 Kiro Auto Allow  v1.0.0
 Kiro の「Allow」ボタンを自動でクリックするツール
==========================================================

■ このアプリについて

Kiro を使っていると、コマンド実行の前に確認画面が表示されます。

    Your approval is required to continue: ...
    [Allow]  [Always allow]  [Deny]  [Always deny]

このアプリを起動しておくと、一番左の「Allow」だけを自動で
クリックします。毎回手で押す必要がなくなります。

「Always allow」「Deny」「Always deny」「Cancel」は
絶対にクリックしません。


■ 動作環境

  ・Windows 11（64bit）
  ・Kiro がインストールされていること

Python やライブラリのインストールは不要です。
この exe だけで動作します。インストール作業もありません。


■ 使い方

  1. ZIP を展開する
  2. KiroAutoAllow.exe をダブルクリック
  3. 「Auto Allow: OFF」のボタンを押して「ON」にする
  4. あとは普通に Kiro を使うだけ

  OFF のときは何もしません。
  終了するときはウィンドウを閉じてください。


■ 初回起動時の警告について（重要）

このアプリにはコード署名（デジタル署名）を付けていません。
そのため初回起動時に次の警告が表示されることがあります。

    「WindowsによってPCが保護されました」
    「Microsoft Defender SmartScreen は認識されないアプリの
      起動を停止しました」
    発行元: 不明な発行元

これは「このアプリが危険」という意味ではなく、
「Microsoft がまだ知らないアプリである」という意味です。
署名証明書は有償のため付けていません。

  ● 起動する手順

      1. ［詳細情報］ をクリック
      2. 画面の下に出てくる ［実行］ をクリック

      ［実行］ ボタンが見えない場合は、ダイアログが画面から
      はみ出しています。次のどちらかで操作できます。

        ・Tab キーを数回押して ［実行］ を選び Enter を押す
        ・Alt + Space →「移動」→ 矢印キーで画面内に動かす

  ● 警告そのものを出さないようにする手順

      ZIP を「展開する前に」ブロックを解除しておきます。

      1. 受け取った ZIP ファイルを右クリック →「プロパティ」
      2. 画面下部の「セキュリティ:」の欄にある
         「許可する」にチェックを入れる
      3. 「OK」を押す
      4. そのあとで ZIP を展開する

      ※ 展開したあとでは効果がありません。順番が重要です。
      ※ この項目は、インターネット経由で受け取ったファイルに
         のみ表示されます。表示されない場合は不要です。

  ● 判断の材料

      信頼できない場合は実行しないでください。
      配布元に確認するか、下記「安全対策」の内容を読んでから
      判断してください。


■ 画面の説明

  Auto Allow: ON / OFF
      自動クリックのスイッチ。OFF のときはクリックしません。

  完了通知: ON / OFF
      Kiro の処理が終わって次のプロンプトを送れる状態になったら
      知らせます。音を鳴らし、タスクバーを点滅させ、ウィンドウを
      一時的に最前面に表示します（5秒後に自動で元に戻ります）。
      キー入力は奪いません。

  緊急停止
      監視を即座に止めます。

  現在の状態 / Kiro / クリック回数 / 検出回数
      いまの動作状況です。

  Allow した内容（新しいものが上）
      実際に許可したコマンドの内容が新しい順に並びます。

  ログ欄
      検出・クリック・見送り理由などの記録です。

  ［UI要素を確認］
      うまく動かないときの調査用です。Kiro から読み取れた
      ボタン情報をテキストに書き出して開きます。


■ 止めたいとき

  ・画面の ［緊急停止］ ボタンを押す
  ・Esc キーを素早く2回押す
  ・「Auto Allow: ON」を押して OFF にする

  Esc キーは横取りしていないので、他のアプリの操作を
  邪魔することはありません。


■ 安全対策

次の条件をすべて満たしたときだけクリックします。

  ・ウィンドウを所有するプロセスが kiro.exe であること
  ・ウィンドウクラスが Chrome_WidgetWin_1 であること
  ・要素の種類が Button であること
  ・ボタン名が「Allow」と完全一致すること
    （Always allow や allow は一致しないので押しません）
  ・同じ承認ブロック内に Always allow と Deny があること
  ・その Allow が同じ行の一番左にあること
  ・ボタンが有効で画面内にあり、Kiro のウィンドウの内側にあること
  ・要素の所有プロセスIDが Kiro と一致すること

クリックする直前にもう一度すべて確認し、条件が崩れていれば
中止してログに残します。

Kiro 以外のアプリやブラウザに表示された「Allow」は
対象になりません。

画面の座標を決め打ちしていないため、解像度やウィンドウの
大きさ・位置が変わっても動作します。

1分間に12回を超えてクリックした場合は、異常とみなして
自動的に停止します。

クリックは Windows UI Automation を使用しており、通常は
マウスカーソルを動かしません。


■ 保存されるファイル

  C:\Users\(ユーザー名)\AppData\Local\KiroAutoAllow\

      config.json   設定ファイル（初回起動時に自動作成）
      logs\         日付ごとのログ
      ui_dumps\     UI要素の書き出し

exe をどこに置いても、保存先はこの場所になります。
設定はプロジェクトやリポジトリとは無関係で、Windows の
ユーザーごとに1つです。


■ アンインストール

  1. KiroAutoAllow.exe を削除する
  2. 上記の KiroAutoAllow フォルダを削除する

レジストリは変更していません。
インストーラも使っていないので、それ以外の作業は不要です。


■ うまく動かないとき

  「Kiro のウィンドウが見つかりません」と出る
      → Kiro を起動し、最小化を解除してください。

  何も反応しない
      → 「Auto Allow」が ON になっているか確認してください。

  「承認 UI と確認できませんでした」と出る
      → Kiro の更新でボタン名が変わった可能性があります。
        ［UI要素を確認］でボタン名を確認し、上記フォルダの
        config.json の target_button_name を合わせてください。

  「Invoke は実行できましたが承認 UI が残っています」と出る
      → Kiro のウィンドウを手前に出しておいてください。


■ 技術的な補足

  ・画像認識は使用していません。Windows UI Automation で
    UI 要素の名前と構造を直接読み取っています。
  ・PyInstaller でビルドした単一ファイルの実行ファイルです。
    必要なランタイムとライブラリは exe に同梱されています。
  ・ネットワーク通信は行いません。
